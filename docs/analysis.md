# Analysis internals

Stillset decodes every video frame in timestamp order, requests compact YUV buffers, and renders batches of eight into grayscale proxies with a bounded task group. Results are restored to timestamp order before motion detection. Motion is measured on a 6 × 6 grid without copying whole frames into temporary arrays. Persistent movement in a localized region is treated as animation so it does not hold the whole screen in motion. Stable pauses of at least 40 ms are retained; pauses shorter than the 120 ms confirmation threshold are still exported. The sharpest, calmest frame in each interval supplies the export timestamp; the PNG itself is re-extracted from the original video.

Finalized detector callbacks admit original PNG export during decoding, including the last occurrence once at EOF. Features owns one pending export task and a chronological buffer of at most four finalized states. The first state starts export immediately. Later states fill four-state batches, waiting for the active job only when the buffer is full. EOF drains the active job and exports the remaining one to three states. Sparse captures after the first can wait for a full batch or EOF. There are no task chains or per-occurrence jobs. Decoder callbacks contain at most eight finalized states. Staging is attached before decoding, and committed PNGs become selectable immediately. Decode progress remains active while PNGs arrive. EOF closes admission and drains export before organization begins. Export errors propagate through the next full-buffer admission or final drain. Cancellation cancels and awaits export and prepared recognition before analysis releases ownership. Committed captures survive cancellation and errors. The completed result is never exported a second time.

Screen classification runs separately from capture selection. The hybrid analysis requires macOS 27 and keeps all processing local. One analyzer belongs to each accepted recording. It retains successful image evidence by the original PNG's SHA-256 digest, independently of naming mode or filename. Each extraction builds one transformed thumbnail with an 800-pixel maximum. Accurate Vision OCR, comparison sampling, and recognition's visual evidence use that same image. The decoder's 400-pixel grayscale proxy is used only for detection. PNG data is hashed sequentially, then reloaded only in the two continuously refilled extraction slots. The first committed original PNG starts prepared recognition before UI delivery. Matching prepared evidence occupies one extraction slot and is adopted without duplicate OCR. Mismatched, unused, or cancelled preparation is cancelled and drained. Extraction releases full PNG snapshots and thumbnails after completion. Failed OCR remains retryable. Successful readings with no title are retained too, so model fallback does not repeat those readings. The initial pass uses visible titles for naming and preserves unresolved states separately. Background refinement uses Foundation Models only for ambiguous grouping and names, including form state. Reliable visible titles still bypass the model; repeated inset form labels, uncertain headings and unknown surfaces use image analysis. A centered bright heading over a dimmed page identifies common bottom sheets, so the foremost picker overrides the background page. Forms receive empty, partially filled, filled or error state suffixes. Recognized titles are reused on model failure without repeating OCR. One bounded retry handles transient model errors; refusals go directly to fallback.

A small grayscale comparison nominates up to three nearby representatives (mean distance at most 8/255). Reliable text substitutions, added badges and substantially different visible content can reject matches locally. Matching text requires visual evidence before grouping: a conservative RGB tile comparison checks the foreground, while small numeric-list scrolls match the option labels, then compare the visible central band of their controls on both sides of the text. This avoids glyph rasterization differences and sticky-header clipping while preserving selection changes. The header is checked separately and the scrollbar gutter is excluded. Ambiguous pairs remain separate in the initial pass and alone use a structured Foundation Models image comparison during background refinement. Uncertain or failed comparisons retain separate states. These heuristics are experimental and need validation on real recordings, particularly unfamiliar overlay and control layouts. All timeline occurrences and original-resolution exports remain intact.

States are grouped before naming, so repeat visits reuse one naming request. Model sessions are created only if unresolved names need them, then prewarmed during grouping. Naming keeps two requests active with fixed chronological OCR titles and cached names as context; completion order cannot change prompts. A new import cancels and drains the previous refinement before deleting staging. Operation identities guard queued progress and terminal results, so stale callbacks cannot overwrite a newer recording. Named links from the initial pass remain valid for existing clipboard and drag references. Semantic comparisons remain serial: a two-worker trial was slower and less reliable on the local model. SHA-256 shares evidence for byte-identical captures without removing occurrences. Grouping is recomputed chronologically for each naming mode. The last catalog and successful derived names are scoped to ordered content, naming policy, and representative grouping. Successful names and comparison decisions, including different-state results, survive partial retries within those scopes. Comparison results are cached by the two image digests (up to 512 pairs); failures and cancellations are not cached. The app indicates names supplied by Vision. If both methods fail, it displays Capture à examiner, with the chronological index kept in filenames. FeaturePrint nomination was removed after it excluded small scrolls from semantic review on real exports.

PNG export uses AVFoundation’s native batched image sequence with zero timestamp tolerances. Batches retain at most four original frames; PNG encoding is serialized through the video’s processing lane and shares the session’s two-job limit. Each completed encoder result publishes the contiguous chronological prefix without waiting for later encoders. At most four results wait for their turn. Callbacks remain batch-local and filenames use global occurrence ordinals, including duplicate timestamps.

Staged PNGs use recording-order indices and safe screen names, for example `007_simulation-de-revenus-choix-de-marque.png`. Repeated visits retain their own index. Display names never contain em dashes. Clipboard and drag preserve these source filenames and recording order. Staging names are hard links (or copies if linking fails), so references to the original streamed files remain valid during the session.

SAVE snapshots selected visible captures, screen names, source URLs and layout before the destination chooser. Chronologie uses chronological order in one folder. Par écran projects the existing timeline groups, retaining first-appearance rank even when the earliest capture is unselected; members stay chronological. Its default single-folder layout assigns dense global numbers, such as `001_compte.png`. Optional screen folders use group numbers and per-group capture numbers, such as `001_compte/001_compte.png`. Equal-name screens remain separate groups; unclassified captures use À identifier. Both staging and SAVE share the safe 64-character screen-name slug policy. SAVE copies the original PNG bytes into independent files, never renaming or linking sources. Existing files, directories and symlinks are preserved with collision suffixes; group folders are created exclusively rather than reused. Cancellation or an error keeps completed output, and progress counts files across all groups.

Features owns one injected typed UserDefaults preferences object shared with the native Settings scene. Missing or invalid values fall back independently to Uniques, Chronologie and single-folder export. Capture and organisation defaults are sampled at model initialization and accepted import; current session controls and selection do not persist defaults. Export layout is sampled with each SAVE plan. Analysis, refinement, and SAVE each own their identity, task, progress, and terminal outcome. SAVE reserves ownership before the destination chooser and copies its frozen plan even if selection, naming, or layout changes. SAVE never replaces the analysis task or progress. Session replacement cancels and drains prior work before deleting its staging; SAVE retains ownership of its frozen sources until it finishes. Refinement can continue alongside SAVE. Separate accessible cancel controls target each operation. Every queued progress update and terminal callback checks its operation identity.

Videos are queued in import order with at most two simultaneous analyses. Each video owns its processing lane, staging, progress, and cancellation; a cancelled video retains completed captures. The session timeline orders videos by import ordinal and captures by local timestamp, independent of callback completion order. A local catalog over immutable terminal capture snapshots joins positively matched states across videos. Names alone never join groups. Session refinements preserve accepted evidence for unchanged captures.

## Current limits

Active export and extraction work is bounded. Successful evidence remains in memory for the recording, without eviction, disk caches, or sidecars. Retained evidence grows with unique content, and occurrence metadata grows with captures. This is not a constant total memory guarantee for arbitrarily long recordings. Supported recordings need peak-memory profiling before any spill policy is added. Full-resolution presentation previews remain unchanged.

The synthetic corpus exercises two scroll stops, navigation, return to an already-seen screen, full-resolution export, and copying exported PNGs; it is not a set of recordings from every listed iOS interaction. Generated-image tests cover exact duplicate grouping and safe indexed filenames. Synthetic OCR evidence tests cover small scrolls, changed selection controls on either side of the labels and fixed-header differences; they do not exercise Vision recognition end to end. Feature tests cover selection and dragging in the unique-screen view. Names remain proposals, not measured recognition accuracy. Semantic names alone never determine which captures are hidden. Direct image understanding can produce incorrect names or grouping. OCR bounding-box jitter can leave an equivalent scroll ambiguous; it remains separate. Contextual naming is optional and does not change which timestamps are retained. Localized animation masking is intentionally limited to regions covering at most 30% of the frame, so a large continuously moving video preview can still interrupt stability detection. Sessions are not restored between launches; the bounded recent-analysis cache retains metadata for reuse on a later import.
